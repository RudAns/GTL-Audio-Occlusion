声音遮挡 / 阻挡 / 衍射：UE5 落地要点

GTL-Audio-Occlusion · 技术落地文档 · UE 5.8

本文把 GTL-Audio-Occlusion 里每一层的做法、参数和踩过的坑整理成可以直接搬进项目的形式。代码位置都写在小标题后面，路径相对 Source/AudioOcclusion/。引擎版本 UE 5.8，测试机 i7-13700KF + RTX 3060。

1. 先定结构：一个声源三条声部

每个声源组件（AcousticEmitterComponent）创建三个同步播放同一素材的 UAudioComponent：

声部 位置 用途
路径声部 虚拟声源（门口方向，距离 = 路径长度） 绕门传来的主声音
透射声部 声源真实位置 穿墙分量，和路径声部在空气里按能量相加
Steam 声部 声源真实位置，挂 Steam 遮挡插件 方案对照用，项目里二选一即可

不用的声部把音量压到 0.0005，而不是停掉，这样切换方案时循环素材不会错位。这些声音资源要设成 PLAY_WHEN_SILENT，否则被虚拟化后再恢复会错相位。一次性声音（脚步）用同一套声部：每次落地时三条声部一起 Play()，增益、滤波和位置由求解器持续写在组件上，重放时自动生效。

分频段增益的施加方式（AcousticEmitterComponent::ApplyBands）：求解器给出 250 Hz / 1 kHz / 4 kHz 三个频段的 dB。中频直接换算成 VolumeMultiplier；低频和高频相对中频的差值写进每个声部独立一份的 USourceEffectEQPreset（180 Hz、4.5 kHz 两个峰值段，带宽 2 个八度）；高频比中频低 10 dB 以上时，再开组件自带的一阶低通，截止频率 20 kHz × 2^((ΔHigh+10)/4)，下限 400 Hz。EQ 预设必须每个声部 NewObject 一份，共享会互相覆盖。

求解频率：所有声源 15 Hz 轮流求解（SolveRateHz），结果再经平滑。6 个声源在测试机上每帧 0.06~0.9 ms（波动烘焙模式最高）。

2. 几何准备

  • 专用碰撞通道：DefaultEngine.ini 新建 ECC_GameTraceChannel1（名为 Acoustic，默认 Block）。所有声学射线都走这个通道，角色胶囊、家具、灯具对它 Ignore，墙、门、柱子 Block。
  • 坑：代码里改碰撞响应的 UStaticMeshComponent 要先 bUseDefaultCollision = false 并设 BlockAll profile，否则关卡重新加载后按网格默认碰撞恢复，家具会挡住声源。
  • 材质：用组件标签 TL_Wood / TL_Glass / TL_Door / TL_Furniture 标出隔声材质，没标的按混凝土。分频隔声量（dB，250 / 1k / 4k）：
材质 250 Hz 1 kHz 4 kHz
混凝土 42 52 60
木隔墙 14 22 30
玻璃 18 26 30
木门 16 22 27
家具 4 8 12
  • 房间与门洞：AAcousticRoom 是一个轴对齐盒子（带混响时间、湿声电平、是否室外）；AAcousticPortal 是门洞盒子，前向 = 法线，开度由门的转角换算（sin 映射，转到 70° 视为全开）。门洞两侧的房间在 BeginPlay 时沿法线 ±60 cm 探测自动连接。

3. 单射线与多射线（同一空间内的阻挡）

AcousticSubsystem::MultiRayFraction

  • 引擎原生遮挡（bEnableOcclusion）只有一条射线、二值结果。默认参数是低通 20 kHz、音量 1.0，打开后什么都不会变，必须改成例如 600 Hz / 0.25；本工程设 OcclusionTraceChannel = Acoustic、插值 0.1 s。实测被挡时整体低约 12 dB。
  • 多射线：以声源为中心取二十面体 12 个方向、半径 40 cm 的点，先剔除“从声源到采样点就被挡”的点（贴墙的声源不会有一半射线打进墙里），再统计到听者被挡的比例 F。
  • 只开多射线时：增益 = (−10F, −18F, −26F) dB。
  • 开了门户路径时，多射线只用来算同一房间内的阻挡：(−3F, −8F, −15F) dB，只衰减直达声。
  • 声源离地太近时，下半圈采样点会进地板。脚步声源放在离地约 30 cm。

4. 房间—门户路径与衍射

AcousticSubsystem::FindPortalPath、SolveCustom、KurzeAndersonDb

  1. 用房间盒查出声源房间和听者房间。同一房间时只做第 3 节的阻挡。
  2. 图的节点是声源、听者和每个开着的门洞（门开度低于 2% 视为不通），两个节点属于同一房间就相连，边权为直线距离，Dijkstra 找最短的门洞序列。
  3. 拉紧：路径点先放在门洞中心（耳朵高度），再迭代 3 遍：每个门洞点取“前一点—后一点连线”与门洞平面的交点，夹到开口范围内（ClosestPointOnOpening），得到贴着门框的折线。
  4. 视线捷径：声源到听者的直线如果本身没被挡（正好对着门口），损失直接为 0，否则会在“几乎看得见”的位置凭空衰减 5 dB 左右。
  5. 衍射损失（每个频段）：程差 δ = 路径长 − 直线距离，菲涅耳数 N = 2δf/c，损失 = 5 + 20·lg(√(2πN) / tanh√(2πN))，上限 24 dB。对照的角度映射按累计拐角 θ：(−4, −10, −18) × min(θ, 270°)/180°。
  6. 门的开度另算：每个经过的门洞叠加 10·lg(max(开度, 0.03)) dB。
  7. 虚拟声源：从听者沿“路径最后一段”的方向放到距离 = 路径长度处。这样引擎的距离衰减和 HRTF 方向都自然正确，不用另算。

5. 穿墙透射

AcousticSubsystem::TransmissionLoss

只在直达声被挡时算：沿声源到听者的直线反复做射线检测，每碰到一个构件就加上它的隔声量并把它加入忽略列表，最多 10 层，总量封顶 60 dB（侧向传声）。结果作为透射声部在声源真实位置播放，和路径声部是两条独立的声音，在空气里按能量相加。门全关时路径声部静音，只剩透射声部。

6. 房间混响耦合

AcousticSubsystem::InitAudioGraph、ApplyResult、UpdateRoomCoupling

  • 每个室内房间一个运行时 USoundSubmix，效果链为 [SubmixEffectReverb（湿 1、干 0，衰减时间取房间参数）→ SubmixEffectFilter 低通]，用 FAudioDevice::RegisterSoundSubmix 注册。
  • 每个声源只发送到自己所在房间的子混音，其他房间发送 0。
  • 每个房间子混音的输出音量和低通代表“这个房间的混响传到听者房间还剩多少”：沿门户路径每过一个门 −6 dB 再加 10·lg(开度)，低通 9 kHz / (1 + 0.6 × 程差米数)（900 Hz ~ 20 kHz）；不连通时按墙体隔声，低通 500 Hz。听者所在房间为 0 dB、20 kHz。
  • 重要的坑（UE 5.8）：对 HRTF（插件空间化）的声源使用 ESubmixSendStage::PreDistanceAttenuation 发送时，混音器把单声道的衰减前缓冲当成双声道读，产生 NaN，整个主混音会变成静音（录出来是满幅直流）。本工程改为衰减后发送，再把距离增益除回去，效果等价：
const float G = Attenuation.Evaluate(FTransform(VoicePos), ListenerPos, 1.f);   // FSoundAttenuationSettings
Info.SendLevel = FMath::Min(WetLin / FMath::Max(G, 0.02f), 50.f);
Info.DisableManualSendClamp = true;                                            // 允许 > 1
Info.SendStage = ESubmixSendStage::PostDistanceAttenuation;
AudioDevice->SendCommandToActiveSounds(Comp->GetAudioComponentID(), [Info](FActiveSound& AS) { AS.SetSubmixSend(Info); });

SetSubmixSend 对一次性声音也要每次求解都重发（每次 Play() 都会生成新的 ActiveSound）。

7. 时间平滑

增益在 dB 域做一阶平滑，时间常数 0.2 s。虚拟声源位置不能直接线性插值（会从墙里穿过去），要把“方向”和“距离”分开：方向用四元数 Slerp，距离线性插值。目标位置非法（NaN）或离听者不足 1 cm 时退回线性插值，避免 FindBetweenNormals 遇到零向量。

8. GPU 波动烘焙

Source/OcclusionWave（RDG 计算着色器）、Shaders/WaveFDTD.usf、WaveBakeActor

求解器：压力形式的 3D FDTD，7 点模板，蛙跳积分，λ² = (cΔt/Δx)² = 0.25（Courant 0.5，三维稳定上限 0.577）。格子 Δx = c / (5 × f_max)，f_max = 500 Hz 时为 13.7 cm。墙格用镜像邻居（刚性 Neumann 边界），贴墙格每步乘 0.985 模拟吸收，域边界 10 格二次吸收层（最大 0.08）。声源为高斯脉冲，σ = √ln10 / (π f_max)，t0 = 5σ（Raghuvanshi & Snyder 2014）。每个探针模拟 0.92 s（4600 步）。

体素化：只收标了 Acoustic 的网格组件（不含门板，门洞一律按打开烘焙），按包围盒转体素。厚度不足 2 格的墙沿最薄轴加厚到 2 格，否则声波会从一格厚的墙漏过去。

记录与归约：每 4 格取一个采样点（55 cm），每 6 步累加一次 p² 得到能量包络。CPU 端： - 参考电平：探针 0.8~1.8 m 处最强采样点的直达能量，换算成相对 1 m 自由场。 - 首达时间：包络第一次超过参考峰值 −50 dB 的时间，减去 t0。 - LDS（直达声）：首达后 5 ms + 4σ 窗内的能量；LER（早期反射）：其后到 200 ms。

探针：每个房间按盒子均匀铺（室内约 2.6 m，室外 5 m，保证窄走廊中线有一排），离墙至少 3 格；每个门洞两侧 75 cm 各加一个。本场景 90 个探针，测试机上烘焙约 98 秒（显卡被其他程序占用时会翻倍）。结果连同几何哈希存盘，几何不变时直接读取。

运行时查询： 1. 选探针：与听者同一房间、到听者无遮挡的最多 3 个，按 1/r² 加权。只取最近的一个探针时，常会选到门洞对面另一个房间的探针，参数会跳。 2. 互易性：探针当耳朵，在声源位置三线性插值读首达 / LDS / LER，加权混合。 3. 额外损失 = 自由场(路径长) − LDS；湿声 = LER − LDS − 14 dB（限制在 −30 ~ −4 dB）。高频没有算到（f_max = 500 Hz），用“能解释这个低频损失的等效程差”代回 Kurze–Anderson 外推 1 kHz / 4 kHz。 4. 方向：从声源沿首达时间梯度往回走（步长 20 cm，每步检查不穿实心体素），一旦能直接看到听者就停，最后一个拐点就是声音来向，虚拟声源放在这个方向、距离 = 首达时间 × c。 5. 关门：烘焙时门是开的。运行时检查路径线段与门平面的交点是否落在门洞内（不能用线段中点：最后一段直连听者，可能很长），落在门洞内就叠加门的隔声量按开度插值。

为什么 500 Hz：每降一半 f_max，格子数和步数都减少，开销降到约 1/16。500 Hz 足够得到首达时间、直达能量和混响比，高频靠外推。要更准的高频就要提高 f_max，或像 Project Acoustics 那样上云烘焙。

9. Steam Audio 4.8.1 接入 UE 5.8

  • 官方预编译插件的 BuildId 与 5.8 不符，不能直接用。把 steamaudio_unreal 源码拷进工程 Plugins/SteamAudio，删掉 Binaries / Intermediate 后随工程一起编译；工程插件会覆盖引擎自带的旧版。只保留 windows-x64（和需要的 Android ABI）的 SDK 库，并相应修改 SteamAudioSDK.Build.cs。
  • DefaultEngine.ini 把 Windows 的空间化、混响、遮挡插件都设为 Steam Audio，采样率 48 kHz。
  • 静态几何导出 SteamAudio::ExportStaticGeometryForLevel 必须在后台线程调用，同时在游戏线程 ProcessThreadUntilIdle 泵消息，否则会死锁。会动的门要做成 AStaticMeshActor 加 SteamAudioGeometryComponent，用 ExportDynamicObject 单独导出。
  • 声源 Actor 挂 USteamAudioSourceComponent（遮挡用体积模式、半径 0.4 m、开启分频透射），声音的衰减设置挂 USteamAudioOcclusionSettings。遮挡值和三个频段的透射值可从源组件读出，透射值是振幅增益。
  • 本工程只用了 Steam 的直达声遮挡与透射，没有烘焙它的路径（pathing）探针，所以关门后它不会绕门。要绕门可以开 pathing，或者像对照组 6B 那样把自研门户路径叠加上去。

11. 手机端

  • 自研管线（射线 + 门户）开销小，可以直接用；射线数降到 4~6 条，求解频率降到 5~10 Hz，只给附近 8~16 个重要声源求解，其余只用距离衰减。
  • 三声部方案在手机上换成两声部（路径 + 透射），或只保留路径声部、用一个低通近似透射。HRTF 换成普通声像。
  • 波动烘焙只适合离线：烘焙结果每个探针约 0.3 MB（本场景 25 MB），手机上可以只存首达时间和 LDS 两个场、降到 8 位，或者烘焙后只导出“每个门洞的等效损失”给门户路径使用。
  • Steam Audio 支持 Android arm64，但直达遮挡的体积采样和 HRTF 开销要实测，建议关体积采样、只用单射线。

12. 自测方法

Tools/capture.ps1 [-Build] [-Only 22,25] 以离屏窗口启动游戏，由 CaptureDirector 依次摆位、切换开关、注入真实按键和 Slate 鼠标点击，并： - 截图到 Saved/Capture； - 从主子混音挂监听器（ISubmixBufferListener）自己写 WAV，统计 RMS、峰值和非有限样本数； - 把每个声源的求解结果写进 readout.txt。

第 25 组截图逐个开关录音（听者在客厅、琴房收音机独奏）：不处理 −46.9 dBFS；UE 原生被挡 −58.7；门户 + 程差 + 透射 −59.5；加混响 −57.8；波动烘焙关门不叠加衰减 −60.5、叠加后 −80.6；Steam 关门 −88.0。
